## 2026-09-10 · 把整站重做成滚动叙事的 launch 页

**改了什么**

- `index.html`：整站重写为 9 段连续滚动叙事（原先是 89 行的静态页）
- `assets/launch.css`：新增。双场色彩系统、四章进场效果、手电筒、可拖拽标题、降级与移动端
- `assets/launch.js`：新增。WebGL 三场景（3D 手机 / 小物星云 / 收尾点阵）+ 滚动控制器 + 八种 DOM 效果
- `vendor/three.module.min.js`：本地 vendor three.js r169（687KB，用 min 版而非 1.3MB 的完整版）
- `assets/screens/{home,stage,result}.png`：真机 App 截图（1206×2622），作为 3D 手机的屏幕贴图
- `docs/DESIGN.md`：新增。四个基础：叙事结构 / 视觉基调 / 动效语言 / 硬性约束
- `AGENTS.md`：新增。要求任何代理先读设计规范、必须写本日志、不许把未验证说成完成

**为什么**

- **第 03 段不抄"地球"。** 参考站用点阵地球讲"世界"；我们讲"你身边的那件小物"，
  所以做成**小物星云**：6 个剪影（杯/钥匙/叶/伞/书/耳机）各按像素采样成 7000 个点，
  点集按"绕质心的角度"排序后按序号配点做变形 —— 变形不会乱跳。
  数据全部由代码生成，不用 Natural Earth，也不用任何图片素材。
- **明暗只有一次切换。** 01 浅色开场 → 02 转入暗场，之后一路暗到 09。
  所以暗场由 `#s02` 的进度驱动（`> 0.25`），而不是写死的全局百分比。
  08 的手电筒只有在暗场里才成立。
- **手机是真几何真材质。** 圆角矩形挤出 + PBR 金属 + 程序生成的等距环境贴图，
  屏幕贴真机截图。没有用任何外部 3D 模型文件（授权不明，且违反"不加载素材"约束）。
- **时间轴模型修正。** 原先 `spanOf()` 带 lead 参数，段落还没滚完就跑到 1.0，
  导致 04 的黑场在全局 40% 处就提前发生。改成标准的"元素穿过视口"映射：
  `start = top - vh`，`end = top + height`。

**踩到的坑**

1. `坑`：无头 Chrome `--screenshot` 对第 02 段之后**全部截出均匀灰色**。
   `根因`：`--virtual-time-budget` 会把 CSS 过渡冻在中间态（截图取到 `rgb(89,88,86)`，
   正好是 #FBFAF8 → #0E0D0C 的过渡中值），同时 rAF 只跑了 6 帧。
   `绕法`：滚动叙事页必须用真实浏览器驱动 —— 装 puppeteer-core（放 /tmp，不污染仓库），
   用 `page.goto` + 真实等待 + `page.screenshot`。
2. `坑`：JS 里 `driftWords` 报 ReferenceError。
   `根因`：IIFE 里赋值给了一个在 IIFE **之后**才用 `let` 声明的变量（暂时性死区）。
   `绕法`：声明提到 IIFE 之前。
3. `坑`：页面报 `fade is not defined`。
   `根因`：把 `fade` 改名成 `fadeOut` 时漏改了 `cloudMat.size = lerp(..., fade)` 一处。
   `绕法`：改完 grep 一遍旧名字；这类错误 puppeteer 的 pageerror 一抓就准。
4. `坑`：无头验证时看不到 JS 报错（不方便开 DevTools）。
   `绕法`：在 `index.html` 里挂了一个极小的一次性错误钩子，把首个错误写进
   `<html data-err>`，`--dump-dom` 就能读到；生产环境无副作用。
